# FlexMeet ASR v2 实测记录（2026-10-22）

## 已完成的改动

- 客户端只把本机连续采集送入 ASR，远端播放、网络补零不再进入识别；分享切换、真实丢样和退会隔离代次。
- 会议协议 v2：真实来源绑定、草稿修订、统一定稿提交序号、空定稿清草稿、取消/不可用状态、最近 32 条非空定稿快照；客户端均消费服务器确认的文本。
- 音频完整读取后提交，限制长度并拒绝 NaN/Inf/越界 PCM；校验代次、连续包序号和采样位置。来源采用服务器唯一编号，避免系统复用 socket 导致旧字幕串入。
- 本地 ASR 分支 80Hz 状态高通、Silero 0.65/0.35 滞回及 2/3 起声确认、非语音噪声底估计、96–300ms 短回答联合门控、低质量重复/纯标点过滤。
- C ABI v1 与公开布局不变；调优环境变量在创建时固定。异步有界诊断、Unicode 路径、自动 DLL/模型哈希、PCM/WAV 对比、打包与回归工具齐备。

## 自动验证

完整构建：VS 2026 构建 x64 Release 客户端/服务器，固定 whisper 源码用 VS 2022 构建独立 CPU 插件并最后部署。CTest 6/6：字幕状态及质量、分段与滚动边界、音频适配器、诊断往返与损坏检测、指标、异步输入/重置/溢出。公开 C 头文件编译及实际 DLL 的 C ABI 集成检查通过。

真实 Release 服务器 + 独立无界面协议端测试通过。覆盖协议不匹配、来源伪造被绑定、重复/迟到消息、双方发言、晚加入、房主移交、重连唯一来源、240/500ms PCM（含负零）逐位相等、半包与 NaN。实际 DLL 回放产生的 8 条定稿和 12 条协议定稿，两端共 20 条定稿完全一致。详见 `protocol-20261022.json`。

同步延迟使用回环 TCP、直接协议发送和 12 次提交计时，结果见 JSON；这不包含 GUI 发包周期、采集、网络跨机和 Whisper 推理，不能当作完整端到端延迟。

纯零、低电平 DC、确定性宽带噪声与脉冲各 2 秒并附尾部静音，无非空字幕。日志显示只有创建流时的预热解码，测试输入未触发额外解码。新诊断日志丢记录为零。测试是合成噪声，不是真实键盘录音，见 `noise-20261022.json`。

original 使用保存的旧版插件；link-only 关闭新高通、滞回和质量门控，是链路改动后的解码对照；quality 为本轮默认处理。此离线回放不能测量旧版两端混音路径的差异。矩阵在诊断哈希/日志及非识别事件耗时的收尾修正前执行，识别、滤波和分段参数相同。完整摘要保留在 `model-comparison-20261022.json`，事件与日志在 `ASR/.cache/comparison-20261022`。

结论：继续默认 base。small 两种版本 4 线程均过载丢样，8 线程首稿约 2 秒，未达到当前体验要求；本段合成文本上也没有比新 base 更准确。base-q5_1 更省内存但没有提速或准确率优势，不能作为升级结论。medium 未下载或测试，不作为实时默认。

## 尚未完成的现场验收

没有人工标注的真实会议录音，不能给出真实准确率改善百分比；“约 50%”仍只是用户体验反馈。未进行真实麦克风、双机 GUI、10 分钟视频负载或真实键盘声的现场验收，也未测 GPU。保留短回答的状态/质量单元回归通过，但轻声和短答的实际漏识需要同录音回归。

未重新录制旧版双端独立识别的现场诊断音频；仅保存了旧程序并做了同 WAV 插件基线。不能据此声称已找到历史录音中的具体失真或噪声来源。统一来源消除两端各自解码的结构性差异，质量门限仍需真实样本校准。

本轮以 CPU 为主；未安装 CUDA Toolkit，不声称已启用 CUDA。跨机联测、下载、构建、诊断和可选模型方法见 `TESTING-v2.md`。
