## CPU 合成音频诊断

输入为本机离线 SAPI 生成的 11.06秒中文音频，16kHz、单声道、PCM16，参考文本去除标点后 **38字**。按 20ms 实时送入，末尾追加 500ms 静音；模型加载与预热单独计时。两种模型使用相同流式配置、512ms 首次触发、简体中文样式提示、8线程、8秒窗口上限。

| 模型 | 首次非空草稿，相对估计起声点 | 推理 P50 / P95 | 窗口末尾至结果 P50 / P95 | CER |
|---|---:|---:|---:|---:|
| 多语言 tiny | 723ms | 218 / 235ms | 205 / 233ms | 18.4%（7处替换） |
| 多语言 base | 943ms | 489 / 588ms | 486 / 742ms | 7.9%（3处替换） |

上述两次均无 GAP、ERROR、漏字或插字。指标中的 P50/P95 是单次回放内多个识别窗口的统计，不是多场会议或多次冷启动的统计。首次草稿各只有一次观测，均在 1秒以内；后台负载未做严格隔离，不能据此声称会议全链路达标。

最终文本：

- 参考：大家好，今天我们讨论轻会议项目的语音识别。我们需要降低字幕延迟，同时减少错字和漏字。
- tiny：大家好。今天我们讨论 亲会议项目的语音时别。我们需要降低自目言值。同时渐少错字和漏字。
- base：大家好今天我们讨论清会议项目的与音时别。我们需要降低字幕延迟。同时减少错字和漏字。

额外将 base 窗口上限强制设为 3秒（该回归使用 640ms 首次触发），验证了真实 token 时间戳的滚动边界路径：5次最终事件，其中发生强制跨窗，未出现 GAP/ERROR。该样本最终 CER 为 2.6%（1处替换，0漏字、0插字）。这只是边界回归诊断，默认窗口仍为 8秒，不能用单个样本选择全局最优窗口。

完整事件见 `tiny-cpu.json`、`base-cpu.json`、`base-rollover.json`；音频哈希、参考和环境见 `fixture.json`。CER 去除标点、空白并忽略字母大小写；不自动转换繁简体。

## 验证范围和限制

- 合成音频不是会议准确率证据；本仓库没有人工标注会议语料。上述差异仅适用于这个短样本，也未重新测量旧插件的整体会议表现。
- `audio_end_to_event_ms` 从结果覆盖的音频窗口末尾计时，终点包含 VAD 尾部静音；不是从真实最后一个字说完到字幕显示的完整延迟。首次起声点由振幅门限估计，未做人工时间标注。
- 未测量实际麦克风、远端传输、多人同时讲话、扬声器回声及界面绘制耗时。当前合并识别默认使用耳机，不提供说话人分离。
- 本机未安装 CUDA Toolkit。已提供 CUDA CMake 构建入口，但 GPU 编译、运行库兼容性、加速效果都尚未验证。当前测试明确使用 CPU。
- 0.5–1秒目标仍需用兼容 CUDA 环境和带时间标注的真实多客户端会议录音验收。
