# 同机双客户端无字幕：诊断与修复

用户运行 Release 服务器与两个客户端，仅一端 share_audio 开启，能听到回传声音。
旧 UI 的 `Audio interrupted; subtitles resumed.` 来自插件 GAP 事件；当前实现中该事件由输入队列溢出产生，不能证明已经恢复。
没有该次真实会话的日志，无法重建每次溢出的具体时间与负载。

## 可复现问题

1. 客户端把接收缓冲超过 200ms 的部分直接裁掉并重置识别。新增回归用连续 240ms 的完整批次，在旧策略下失败：`240ms delivery burst lost continuous PCM before VAD`。这些帧本来没有丢失。
2. 两个真实 ASR 进程使用同样的 11.06秒合成音频、8线程、240ms 到达批次，修复前一路发生推理输入溢出。4线程对照也出现 `ASR input status=2`（OVERFLOW），说明仅调低线程数不能解决。
3. 一次定稿解码完成后，当前批次仍可能解码过期草稿，忽略在解码期间排队的新 PCM；多次推理接连发生，2秒队列可能溢出。
4. 未共享视频时仍连续抓屏/编码，空解码队列仍忙等，给同机测试增加无效负载。

## 修复

- 本地/远端音频各保留 1秒容量，消费时不再裁至 200ms；插入时记录真实丢样并触发重置。
- 调度迟到本身不触发重置；重置以真实丢样为依据。
- worker 检查尚未消费的新音频，积压达到一个草稿间隔时跳过过期草稿，保留所有 PCM 和定稿。默认线程数与 2秒队列不变。
- 未共享视频时暂停连续抓屏/编码；空视频解码队列短暂休眠。
- UI 增加采集状态、样本数、麦克风/ASR 输入音量和中断计数，修正“已恢复”的误导提示。采集启动日志记录实际设备名。

## 验证

- 完整 Release x64 构建、CTest 4/4、C ABI 实际 DLL 集成检查通过。
- 新增原生 `asr_pipeline_test`：复用客户端 PCM 队列适配器、混音函数和实际插件；两个进程同时运行，一个走本地加回传去重路径，一个走远端路径。每 240ms 送入一批、每 20ms 消费。
- 修复后两路各消费 176,960 样本、各产生 4 次定稿；本地 12 个非空事件、远端 11 个非空事件，均 GAP=0、ERROR=0。
- 本次双进程样本部分推理耗时超过 1秒，不代表已满足真实会议 0.5–1秒延迟目标。
- 尚未通过真实麦克风/服务器/界面进行自动化完整验证；原生测试覆盖共享的客户端音频适配器与插件，不覆盖网络协议和图形界面。原始日志在忽略目录 `ASR/.cache/pipeline-fixed-{local,remote}.log`。

